# RecruitAI 与现有 SQL Server 2008 R2 共存部署方案

## 1. 已确认约束

- 生产服务器已有其他业务应用；
- 现有 SQL Server 2008 R2 Enterprise 64 位实例不能升级主版本；
- 当前构建为 `10.50.1600.1 RTM`；
- RecruitAI 必须避免影响其他应用和数据库；
- RecruitAI 数据库兼容级别固定为 100。

## 2. 本次采用方案

RecruitAI 在现有 SQL Server 2008 R2 实例内使用独立数据库和独立账号，不修改其他数据库，不调整实例级配置，不使用 SQL Server 2012+ 语法或功能。

```text
现有 SQL Server 2008 R2 实例
├── 原有业务数据库          保持不变
├── 原有登录与作业          保持不变
└── RecruitAI              新建独立数据库
    ├── RecruitAIWeb       Web 专用登录/用户
    └── RecruitAIAgent     AI Agent 专用登录/用户
```

应用层兼容措施：

- .NET 使用已通过本地 SQL Server 2008 R2 测试的 `Microsoft.Data.SqlClient 7.0.2`；
- Python 使用已通过测试的 ODBC Driver 17 + `pyodbc 5.3.0`；
- 连接串明确设置 `Encrypt=false;TrustServerCertificate=true`，仅作为旧数据库内网兼容方案；
- 禁止使用 `ISJSON()`、`OFFSET/FETCH`、原生向量、Temporal Table 等高版本功能；
- JSON 使用 `NVARCHAR(MAX)`，由 .NET/Python 校验；
- 向量使用 `VARBINARY(MAX)`，相似度计算在 Python 完成；
- 分页使用 `ROW_NUMBER()`；
- 时间使用 `DATETIME2(3)` 和 `SYSUTCDATETIME()`；
- 正式文件存储在 `C:\Zhaopin\Resume`，上传和 AI 分割中间文件存储在 `C:\Zhaopin\ResumeTemp`，知识Excel临时文件存储在 `C:\Zhaopin\KnowledgeTemp`，不把 PDF/DOCX/XLSX 二进制写入数据库。

## 3. 禁止操作

本次 RecruitAI 部署不得执行：

- 升级、卸载或重装现有 SQL Server 实例；
- 修改原有数据库兼容级别；
- 修改原有登录账号或权限；
- 修改实例排序规则；
- 修改服务器级最大内存、并行度等配置；
- 修改现有 SQL Agent 作业；
- 修改现有数据库恢复模式；
- 在未评估其他应用时禁用 TLS 1.0/1.1；
- 使用 SA 作为 RecruitAI 应用连接账号；
- 对其他业务数据库执行结构或数据变更。

## 4. 上线前安全检查

### 4.1 必须备份

- 完整备份现有业务数据库；
- 备份 `master` 和 `msdb`；
- 导出现有登录账号、SQL Agent 作业和链接服务器配置；
- 对备份执行可恢复性验证；
- 记录当前 SQL Server 服务账号、端口和启动参数。

### 4.2 只读检查

```sql
SELECT @@VERSION;

SELECT
    SERVERPROPERTY('ProductVersion') AS ProductVersion,
    SERVERPROPERTY('ProductLevel') AS ProductLevel,
    SERVERPROPERTY('Edition') AS Edition,
    SERVERPROPERTY('Collation') AS ServerCollation;

SELECT
    name,
    compatibility_level,
    recovery_model_desc,
    state_desc
FROM sys.databases
ORDER BY name;

SELECT
    DB_NAME(database_id) AS DatabaseName,
    MAX(backup_finish_date) AS LastFullBackupTime
FROM msdb.dbo.backupset
WHERE type = 'D'
GROUP BY database_id
ORDER BY DatabaseName;
```

### 4.3 Service Pack 与 TLS

“不能升级 SQL 主版本”不等于“不能安装 Service Pack/安全补丁”。建议另行安排兼容性评估：

1. 克隆或恢复生产数据库到隔离测试环境；
2. 安装 SQL Server 2008 R2 SP3、适用 GDR 和 TLS 1.2 更新；
3. 对全部原有应用执行回归测试；
4. 只有全部通过后，才安排生产维护窗口；
5. 若任何补丁也不允许安装，必须记录 RTM/EOL/TLS 风险，并使用网络隔离、最小权限、备份恢复和监控补偿。

补丁不是本次 RecruitAI 首次部署的自动操作，不得未经原有应用负责人批准直接执行。

## 5. 数据库账号建议

生产环境创建两个专用 SQL 登录：

- `RecruitAIWeb`：岗位、候选人、简历元数据、评分配置、查询和 HR 操作；
- `RecruitAIAgent`：AI 任务、结构化档案、评分结果、知识库和清理日志。

账号要求：

- 只映射到 `RecruitAI` 数据库；
- 不授予 `sysadmin`、`serveradmin`、`securityadmin` 或 `db_owner`；
- 使用独立强密码；
- Web 与 Agent 不共用密码；
- 密码只保存在生产配置或安全密钥存储中；
- 默认数据库设置为 `RecruitAI`；
- 定期轮换并验证服务重启。

具体最小权限在业务存储过程/数据访问层确定后再固化；开发阶段可暂时使用 RecruitAI 数据库内的 `db_datareader`、`db_datawriter` 和受控的存储过程执行权限，不授予其他数据库权限。

## 6. 资源隔离

为避免 AI 批处理影响原有应用：

- Web“上传简历”只扫描临时来源目录、认领最多100个文件并生成待审阅批次；HR确认后才创建任务，Web不同步等待AI；
- Python Worker 默认并发设为 10，并通过 `WORKER_CONCURRENCY` 调整；
- 每次扫描最多认领 100 个源文件，但数据库写入仍按文件/分割结果使用短事务执行；
- 合并源文件分割后超过100份正式简历时继续完成当前批次，Agent最多10个执行单元并发写入；
- HR确认前不调用DeepSeek、不生成预解析结果，避免无效Token消耗；
- 分割后单份简历超过20MB时先在副本中安全去除部分图片并校验文本不变；失败文件进入异常区，不自动重试或删除，由HR人工清理；
- 生产无杀毒软件，PDF/DOCX/XLSX仅通过解析库读取文本和必要结构，不启动Office、浏览器、Shell，不执行宏、脚本、附件、外链、OLE或超链接；
- 任务查询使用已有索引，禁止高频全表扫描；
- 大文本和向量不进入候选人列表查询；
- AI API 并发与 SQL 写入并发分开限制；
- 监控 SQL CPU、内存、磁盘延迟、阻塞和日志增长；
- 高峰期暂停批量分析，不影响 HR 查看历史结果；
- 数据库文件使用固定 MB 增量，不使用百分比自动增长；
- SQL Agent 备份作业与 AI 批处理错峰运行。

## 7. TLS 与连接建议

当前 SQL Server 2008 R2 RTM 是否支持安全启用 TLS 1.2 尚未完成验证。上线初期建议：

- Web/Agent 与 SQL Server 置于受控内网；
- 防火墙只开放实际应用服务器到 SQL 固定端口；
- 不通过公网访问 SQL Server；
- 连接串暂用 `Encrypt=false;TrustServerCertificate=true`；
- SQL 登录仍会依赖底层协议保护登录交换，需在测试环境验证；
- 原有应用完成 SP3/TLS 1.2 回归后，再统一启用 TLS 1.2 和数据库证书；
- 不为了 RecruitAI 单独修改全服务器 Schannel 策略。

## 8. 备份策略

生产为 Enterprise Edition，可使用 SQL Server Agent：

- RecruitAI 每日完整备份；
- 根据恢复目标安排差异和事务日志备份；
- 简历文件目录与数据库使用同一恢复点编号；
- 备份写入独立磁盘或备份服务器；
- 每月至少执行一次恢复演练；
- RecruitAI 备份作业使用独立名称，不修改原有作业；
- 设置失败通知和磁盘空间告警。

## 9. 未来可选方案

如果以后允许新增而不是升级现有实例，可在另一台服务器或同一受支持服务器上新建独立命名实例，例如 SQL Server 2019：

- 原有应用继续连接 SQL Server 2008 R2；
- RecruitAI 改连新实例；
- 不需要升级或迁移原有业务数据库；
- 可以启用受支持的 TLS、驱动和运维能力；
- 切换只需迁移 RecruitAI 数据库并更新两个应用连接串。

该方案是长期推荐方向，但不作为本次 V1 上线前提。

## 10. 验收条件

- [ ] RecruitAI 创建在独立数据库中；
- [ ] 原有数据库结构、兼容级别和账号均未改变；
- [ ] Web/Agent 使用独立账号且无法访问其他数据库；
- [ ] .NET 和 Python 均通过生产数据库健康检查；
- [ ] 100 份简历任务不会造成原有应用明显性能下降；
- [ ] SQL 阻塞、CPU、磁盘和日志增长处于可接受范围；
- [ ] RecruitAI 数据库和简历文件恢复演练成功；
- [ ] 若继续使用 RTM，风险接受已有书面记录；
- [ ] 若计划安装 SP3/TLS，已完成所有原有应用回归测试。
