# RecruitAI 服务器部署清单

## 1. 生产 .NET 现状判断

截图显示服务器已安装传统 `.NET Framework` 2.0/3.0/3.5/4.x，`v4 Full` 显示 `4.6.01586`。该结果不能证明服务器已安装现代 .NET/ASP.NET Core，也不能替代 Hosting Bundle。

传统 .NET Framework 的精确版本应读取 `Release` DWORD：

```powershell
Get-ItemPropertyValue `
  -LiteralPath 'HKLM:\SOFTWARE\Microsoft\NET Framework Setup\NDP\v4\Full' `
  -Name Release
```

现代 .NET 检查：

```powershell
dotnet --list-runtimes
```

部署目标：`.NET 8 LTS x64`，开发机当前为 SDK 8.0.423、ASP.NET Core Runtime 8.0.29、Hosting Bundle 8.0.29。

生产服务器必须是 Windows Server 2012 或更高版本（x64）。如果实际系统是 Windows Server 2008 R2，.NET 8 不受支持，应升级服务器系统，或将 Web/Agent 放到另一台受支持的服务器，仅远程访问 SQL Server 2008 R2。

开发机现有 Visual Studio 2022 17.14 支持 `net8.0`，可直接打开解决方案进行调试和文件夹发布。

## 2. Hosting Bundle 安装

安装包随发布材料放在 `publish\prerequisites`。必须在实际 IIS 生产服务器上以管理员身份执行：

```powershell
& '.\Microsoft ASP.NET Core Hosting Bundle 8.0_8.0.29_X86_burn_en-US.exe' `
  /install /quiet /norestart /log C:\Temp\dotnet-hosting-8-install.log
```

安装后重启服务器，或执行：

```powershell
net stop was /y
net start w3svc
```

验证：

```powershell
dotnet --list-runtimes
Get-Item 'C:\Program Files\IIS\Asp.Net Core Module\V2\aspnetcorev2.dll' |
  Select-Object FullName,@{Name='Version';Expression={$_.VersionInfo.ProductVersion}}
```

应至少看到：

- `Microsoft.NETCore.App 8.0.29`
- `Microsoft.AspNetCore.App 8.0.29`
- ASP.NET Core Module V2 文件存在

注意：Hosting Bundle 应在 IIS 之后安装。如果先装 Bundle、后装 IIS，必须重新运行 Bundle 选择 Repair。

## 3. Web 发布部署

先以管理员身份创建正式目录和临时处理目录：

```powershell
$resumeDirs = @(
  'C:\Zhaopin\Resume\PDF',
  'C:\Zhaopin\Resume\DOCX',
  'C:\Zhaopin\ResumeTemp\HRUpload',
  'C:\Zhaopin\ResumeTemp\ThirdPartyImport',
  'C:\Zhaopin\ResumeTemp\Manual',
  'C:\Zhaopin\ResumeTemp\Processing',
  'C:\Zhaopin\ResumeTemp\SplitOutput',
  'C:\Zhaopin\ResumeTemp\Failed',
  'C:\Zhaopin\KnowledgeTemp'
)
$resumeDirs | ForEach-Object { New-Item -ItemType Directory -Path $_ -Force | Out-Null }
```

临时文件生命周期：51JOB JSON 进入 `ThirdPartyImport` 并沿用审议确认流程；HR 在 Web 手动上传的 PDF/DOCX 保存到 `Manual\批次号`，批次立即标记为 `PROCESSING`，由独立 `MANUAL_RESUME_IMPORT` Agent 提取文字、调用AI结构化并写入候选人、简历和岗位关系。单份人工上传简历上限20MB，一次最多10份；扫描版PDF需要先完成OCR。只有正式文件已写入 `Resume`、数据库事务已提交且任务成功时，才删除相应临时文件。失败文件不自动重试、不自动删除，由HR在异常页面人工清理并记录原因。

生产服务器没有杀毒软件，因此简历和知识Excel只能由解析库读取文本与必要结构。Web/Agent不得启动Office、浏览器、Shell或外部查看器，不得执行PDF JavaScript、Launch动作、附件、DOCX宏/OLE/外部关系或超链接；链接只保留显示文字，不访问目标地址。知识文件只接受固定模板 `.xlsx`，禁止公式、宏、外链和嵌入对象，临时文件解析入库后立即删除。

1. 将 `publish\web` 全部复制到服务器站点目录，例如 `C:\Zhaopin\Web`；
2. 用 `deployment\appsettings.Production.json` 替换发布目录配置，并在服务器上填写真实连接串；
3. 不要在配置中使用 SA，创建专用最小权限账号；
4. IIS 应用程序池设置为“无托管代码”、64 位、独立应用池；
5. 站点目录授予应用池账号读取/执行权限；
6. `C:\Zhaopin\Resume` 与 `C:\Zhaopin\ResumeTemp` 授予应用池账号和 Python Agent 服务账号所需的最小修改权限；`C:\Zhaopin\KnowledgeTemp` 仅授予应用池账号所需的最小修改权限；第三方导入账号只允许写入 `ResumeTemp\ThirdPartyImport`；清理任务不得拥有删除 `Resume` 的权限；
7. 保留发布自动生成的 `web.config`；
8. 访问 `/api/health` 和 `/api/health/database` 验证。

H5 语音面试还需在生产服务器或密钥管理系统中配置以下进程环境变量，禁止提交到源码或复制到发布包：

- `TencentInterview__Enabled=true`
- `TencentInterview__SecretId`
- `TencentInterview__SecretKey`
- `TencentInterview__SdkAppId`
- `TencentInterview__SdkSecretKey`
- `TencentInterview__CosBucket`
- `TencentInterview__CosRegion`
- `TencentInterview__AsrEngineModelType=16k_zh`

部署后使用 HTTPS 访问 `/interview`。微信内 H5 和浏览器麦克风采集均要求 HTTPS；同时确认服务器允许访问 TRTC、腾讯云 API、COS 和 jsDelivr CDN。

## 4. Python Agent 部署

生产服务器还需：

- 与服务器操作系统兼容的 64 位 Python；
- Microsoft ODBC Driver 17 for SQL Server；
- Python Windows Service 承载方案；
- 独立的生产 DeepSeek Key；
- 到 SQL Server、DeepSeek API 和简历目录的访问权限。

部署步骤：

```powershell
cd C:\Zhaopin\AI-Agent-Service
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

然后只在服务器上编辑 `.env`，填写生产 Key、数据库账号和路径。开发 `.env` 不得复制到服务器。

服务正式注册前先验证：

```powershell
.\.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8100
```

检查：

- `http://127.0.0.1:8100/health`
- `http://127.0.0.1:8100/health/database`
- `http://127.0.0.1:8100/health/deepseek`

## 5. SQL Server 2008 R2 共存项

### 5.1 版本与补丁

在生产库执行：

```sql
SELECT @@VERSION;
SELECT SERVERPROPERTY('ProductVersion'), SERVERPROPERTY('ProductLevel'), SERVERPROPERTY('Edition');
```

原则：

- 不升级、卸载或重装现有 SQL Server 主版本；
- SP3、最后安全更新/GDR 和 TLS 1.2 更新不作为 RecruitAI V1 上线的强制变更；
- 只有在克隆环境中完成全部现有应用回归、具备完整回滚方案并取得负责人批准后，才可在维护窗口安装上述补丁；
- 若共享实例不允许安装任何补丁，记录正式风险接受，并执行网络隔离、最小权限、备份恢复演练和持续监控；
- 任何获批补丁安装前都必须完整备份系统库和业务库，并在测试环境演练。

当前开发实例是 `10.50.4000.0 SP2`，只能作为功能兼容环境，补丁水平不能照搬到生产。

### 5.2 网络与 TLS

- 启用 TCP/IP；
- 生产建议设置固定 TCP 端口；
- 防火墙只允许 Web/Agent 服务器访问数据库端口；
- 若经全部应用回归和审批，可安装 SQL Server 2008 R2 TLS 1.2 更新及受支持客户端驱动；
- 只有确认全部旧应用兼容后，才配置服务器证书和调整加密策略；
- 未完成证书部署前，只能在隔离内网临时使用 `Encrypt=false`；
- SQL Browser 非必需，固定实例端口后可保持禁用。

### 5.3 账号权限

- Web 与 Python Agent 分别使用独立登录账号；
- 禁止应用使用 SA；
- 账号只映射到 `RecruitAI`；
- Web 账号授予业务所需的读写权限；
- Agent 账号额外授予 AI 任务、档案、匹配和知识表的读写权限；
- 禁止授予 `sysadmin`、`serveradmin` 或 `db_owner`；
- 密码只保存在服务器安全配置中。

### 5.4 数据库配置

- 数据库兼容级别保持 100；
- JSON 字段由应用校验，不调用 `ISJSON()`；
- 向量使用 `VARBINARY(MAX)`；
- 数据文件、日志文件和备份目录分开规划；
- 设置合理的初始大小和固定增量，避免按百分比频繁增长；
- 定期更新统计信息和检查索引；
- 监控数据库容量，若生产为 Express 版需特别关注容量和资源限制。

### 5.5 备份与恢复

如果生产使用 Express 版，SQL Server Agent 不可用，使用 Windows 任务计划程序调用 `sqlcmd`：

- 每日完整备份；
- 根据恢复模式安排差异/日志备份；
- 数据库与简历文件使用同一恢复点编号；
- 备份复制到另一磁盘或备份服务器；
- 每月至少完成一次恢复演练；
- 对备份文件设置独立访问权限。

## 6. 已确认的生产服务器信息

- Windows Server 2016 Datacenter；
- 系统版本 10.0.14393；
- 64 位；
- 满足 .NET 8 x64 和 IIS 托管要求。
- SQL Server 2008 R2 Enterprise Edition 64 位；
- SQL Server 构建 `10.50.1600.1`，产品级别 `RTM`；
- SQL Server 2008 R2 与 Windows Server 2016 的组合不受微软支持；
- 现有实例承载其他应用，已确认本次不能升级 SQL 主版本；
- RecruitAI 按独立数据库、独立账号、兼容级别 100 共存部署；
- SP3/GDR/TLS 1.2 只能在全部原有应用完成回归并经负责人批准后安装；
- 若补丁也不能安装，必须记录风险接受并实施网络隔离、最小权限、备份恢复和监控；
- 未来可选独立 SQL Server 2019 命名实例，不影响原有应用，但不作为 V1 上线前提。
